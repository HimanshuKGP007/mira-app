Mira — engineering reference

What the app actually does, end to end

In plain terms: a child says a word, the app decides correct or mispronounced for each sound in it, and everything a parent sees is built from that — on the device, with the one optional cloud step never touching audio.

The live data flow

Stage by stage

01 · Capture

Mic → WAV, in the browser

The child taps the mic, says the word, and the browser records it directly — no plugin, no upload-then-process step.

core/capture.js — Web Audio API, encoded to 16kHz mono WAV client-side
02 · Recognize

One model pass, phone by phone

A speech model built specifically to output phonemes (not words) turns the recording into a probability, frame by frame, over every sound it knows. It's the same family of model research shows is far more accurate than general transcription tools at exactly this job.

facebook/wav2vec2-lv-60-espeak-cv-ft — CTC head, runs locally (CPU/MPS/CUDA), ~1.2GB, cached after first run
03 · Align

Where each sound actually sits

The app already knows the word, so it knows which sounds to expect — alignment finds where in the recording each one starts and ends.

mira_core.ctc_forced_align — Viterbi alignment over CTC posteriors, no external aligner
04 · Score

Correct, or something else

Each sound's window gets a confidence score against the target — how much of the model's certainty landed on the right phoneme versus everything else. Below the line: substituted, omitted, or not scored if the model isn't reliable enough on that sound to guess.

Goodness-of-Pronunciation (GOP), threshold-gated in policy.py
05 · Remember

The browser is the record

Every finished session — which sounds were clear, flagged, or skipped, at which position in the word — is appended to the child's history right on the device. No account, no server database.

core/rewards.js → localStorage, capped at the last 30 sessions
06 · Summarize

Numbers first, then a sentence

The parent screen's counts and trend line are plain arithmetic over that history — true with or without anything else. On top of that, one optional sentence is generated from those exact numbers and checked before it's shown.

server/insights.py — compute_analysis() + Groq call + forbidden-word verifier

Why the keys stay private

  • 1
    Git never sees themserver/.env is gitignored — confirmed with git check-ignore
  • 2
    Clones get a placeholder.env.example ships instead; a fresh clone runs in fallback mode, no crash
  • 3
    The server can't serve its own folderapp.py mounts only core/ and views/ over HTTP — server/ isn't a route
  • 4
    Keys never round-trip to the browserUsed only for outbound calls; responses carry text, never the key
